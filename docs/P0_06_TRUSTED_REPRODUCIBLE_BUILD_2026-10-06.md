## Critical remaining supply-chain gate
The repository still has no package-lock.json and still contains floating "latest" specifications for React, React DOM, Vite and @vitejs/plugin-react. A trustworthy lockfile must be generated by npm from the real registry in a trusted runtime, reviewed, committed, and then CI must switch from npm install to npm ci.

A lockfile was deliberately NOT fabricated by hand and package versions were NOT guessed. That would create the appearance of reproducibility without actually proving the dependency graph.

## Required completion procedure in trusted runtime
1. Clean checkout of reviewed main/release candidate.
2. Node 22 + npm 10.
3. Resolve exact approved dependency versions from registry.
4. Review direct versions, transitive advisories and licenses.
5. Replace floating latest specs with approved exact/range policy.
6. Generate package-lock.json with npm.
7. Clean install using npm ci.
8. Run npm test and npm run build.
9. Run dependency/security review.
10. Commit reviewed package.json + package-lock.json together.
11. Change CI/demo install to npm ci.
12. Re-run clean CI from the committed lockfile.
13. Add dependency review/automated update governance and SBOM/provenance in the production pipeline.
