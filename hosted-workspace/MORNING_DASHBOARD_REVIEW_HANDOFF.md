# Morning action dashboard review — 2026-10-14

The claim dashboard presents recorded priorities, repair-funding blocks, fee balances, review work and waiting details. `/morning-records?id=<claim-id>` edits the supporting records. This review preserves manual priorities and the separation between workflow facts and financial/approval actions.

Funding and fee source snapshots bind filename, MIME, byte size, category, creation date and source identity. Changed sources or duplicate legacy active groups/references hold amounts outside known subtotals. Voided fees cannot be reactivated; existing history is retained and full history lists reject further revisions rather than silently truncating originals. Totals reject unsafe arithmetic. No default fee percentage, net recovery or live bank amount is calculated.

Waiting records bind the exact action opened and its current claim/evidence/shared-job context. A source/action change requires refresh before saving. Prior waiting updates retain server-stamped history. Midnight changes urgency without discarding waiting notes for otherwise unchanged work. Follow-up priority ties use the earliest source/internal follow-up date while retaining the original recorded date. Distinct tasks receive distinct identifiers; corrupt or duplicate browser order entries cannot duplicate priority cards.

Client-upload review uses the current pricing triage source key/disposition and actual portal provenance. Current preparation-run fingerprints include the same complete evidence metadata used by preparation; current proposals are no longer falsely classified stale due to omitted object keys. Reviewed scope comparisons with source gaps return to review; excluded comparisons and voided draws leave open work. Inspection questions participate in actionable priorities. Receipt and ALE source-review gaps appear in the review queue. Routing dates receive source-reviewed priority only when the current routing/source check is available; applicability is still a human decision.

Writes enforce claim ownership/revision and final exact state, evidence manifest and linked shared-job guards. Changed metadata/catalogs cannot silently commit a record. Supporting storage keys remain private. Morning form drafts have navigation protection, copy support, synchronous busy guards and exact opened-source/action bindings. Confirmed saves clear only the submitted draft before refreshing; refresh failure is explicitly reported as a saved record.

Production build is required before publication. Live browser/mobile and real workflow walkthroughs remain pending.
